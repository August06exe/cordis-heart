# 视觉稿 brief：边界与代价（/limits）

你要为「Cordis 思想图鉴」站点出单页视觉稿，页面 slug 是 `/limits`（边界与代价）。这是一篇九页图鉴里最克制的一页：前面的页面越炫，这一页越静，边界感才成立。全文单文件 HTML 交付。

## 一、风格铁律（逐条遵守，评审按此打分）

1. **单墨编辑印刷风**：纸白 `#FAFAF7` 背景，全页唯一墨色钴蓝 `#2148B8`，层次只靠透明度阶梯（.14 基座 / .20 细线 / .70 图解线 / .78 小字 / .82 正文 / 1 标题），不出现第二色相。
2. **对比度红线**：文字对纸白 ≥4.5:1，图解线 ≥3:1，用 node 实算 WCAG（alpha 先在 sRGB 上对纸白合成，再按 WCAG 相对亮度公式算，8-bit 取整口径），不许目测。淡墨 .14/.20 只用于色块与细线，不用于文字。已实算参考值（8-bit）：.78=4.524、.82=4.966、1.0=7.48；.70 图解线 3.778；.14/.20 为装饰豁免。禁止纯黑 `#000000` 与中性灰文字（会被读成第二墨）。
3. **字体**：Noto Serif SC 900 衬线大标题 + Noto Sans SC 正文（400/500/700）。数据/编号场景可预留 IBM Plex Mono。字号跳变线：最大字（display）对本页最小功能字（图注 11.5px 一档）≥5 倍。移动端 display 下限抬到 58px（58/11.5 = 5.04 全程过线），不要用 38px 下限（38/11.5 = 3.30 不过线）。正文 16px 无 5 倍义务。
4. **留白**：空纸占 25%~50%；主对象四周露纸；对齐左缘或 2-3 列编辑网格，所有元素居中是失败形态。
5. **反 AI 味五禁令**：无紫色渐变、无玻璃拟态（backdrop-filter/blur）、无三等分卡片阵列、无「滚动探索 / Scroll to explore」类提示语、无装饰性状态圆点（圆点只在承载真实语义状态时允许，每节至多一个）。
6. **追加禁令（本站定稿新增，同样硬性）**：
   - 无破折号：`—` 与 `–` 在页面可见文本（含 `<title>`、alt、按钮文案）零容忍，连字符 `-` 与间隔号 `·` 不受限。
   - 中点限流：元信息行里 `·` 每行至多 1 个，禁止「foo · bar · baz」串联。
   - 无装饰性节号眉标：禁止「002 · Capabilities」式与「Brand · No.01」式眉标；被正文或图注引用的功能编号（如图 01、条目号）豁免。
   - 禁虚构数字：页面所有数字必须出自下方素材或标明出处，禁止 99.99% 式整数化假数据。
   - 非用户触发的动效每页只允许一个编排时刻。
7. **交付形态**：单文件 HTML（可引用 Google Fonts CDN），内联 SVG 图解，HTML 末尾（`</body>` 前）附一段 HTML 注释形式的设计说明：配色、字体、构图、动效分镜各一两句。

## 二、版式基座（与全站其他八页同源，原样继承）

- **开本**：页面四缘一圈 1px 墨线框（墨 .20），页边距桌面 22px、移动 14px；报头（wordmark 左、folio 右）、正文、页脚三段以 1px 分隔线（.20）切开。报头 wordmark：衬线 900 的「CORDIS」加小号「DSH 的心脏 · 思想图鉴」；folio 放章节名「边界与代价」。
- **色彩令牌**（直接照抄这套）：`--bg: oklch(0.984 0.004 106.5)`、`--fg: oklch(0.449 0.182 265)`、`--ink-14`、`--ink-20`、`--ink-70`、`--ink-78`、`--ink-82` 均为同一 oklch 加透明度 .14/.20/.70/.78/.82。
- **版面字号**：kicker 12px、字距 .42em、墨 .78，每三节最多一个；大标题 clamp(58px, 3.6vw, 72px) 衬线 900（下限就是 58px，见铁律 3）；正文 16px/行高 2.0、墨 .82、列宽上限 26em；图注 11.5px 加 1px 细线、墨 .78、字距 .2em。
- **图解 SVG**：2px 描边、纸白填充、rx 10 圆角积木立于墨 .14 基座条上，依赖/流向关系用 1.6px 贝塞尔曲线加箭头（墨 .70）。面板一律 2px 墨线勾勒，不做填充色区分。
- **无障碍**：`:focus-visible` 2px 墨色外框；满高用 `min-height:100dvh`，禁固定 `h-screen`；<960px 塌单栏且无横向滚动（视口 375/768/1280/1440 四档 `scrollWidth <= clientWidth`）。
- **可靠度徽标**：每节挂一枚三级徽标（论文原文核实 / 合理解读 / 转引未核实），用墨的密度区分（实印 / 网屏点纹 / 细线的印刷隐喻），不引入第二色相。各节建议挂级见下文。

## 三、动效纪律（本页强度 4，克制本身是论点）

- 本页禁钉住（pin）禁滚动擦洗；动效只来自进视口一次性显影和用户交互；只动 transform/opacity，60fps。
- 页面唯一的编排时刻：给「什么时候别用」对照表的逐条显影（每行 stagger 约 60ms、位移 ≤12px 的一次性上浮）。其余节只做进视口一次性的轻交叉淡（或不做动效，只用排版层级）。节与节之间不加第二套编排序列。
- `prefers-reduced-motion` 时全部动效降级：直接定格终态，内容不缺失。
- 对照表行 hover 允许一个极轻的反馈（背景淡墨 .14 一闪或行首标记加实），不做位移。

## 四、内容与结构（素材出处：研读总览第六节「这套思想的边界与代价」，逐条照录，不得虚构）

页面叙事顺序如下，版式族是 **type-led declaration（文案本身即主对象）**：

**第一节 · 最大成本是纪律**（徽标：论文原文核实）
type-led 开篇。大字立骨，核心论点直接排成版面主角：这套范式的前提是「一切共享状态绑成键、一切交互走语境」；论文第 31 页原话划界：**绕过语境的共享位置落在定理保护之外**。采用它是改造，一半状态走语境、一半不走的用法比不用更危险，因为你会误以为有保证。

配一幅内联 SVG 图解（全页唯一的场景图，2px 描边语言）：「语境之门」。中央一座门/关口（语境），左侧两三块状态键积木经门进入右侧组件区（1.6px 墨 .70 曲线，受保护）；另画一条虚线（墨 .20，装饰豁免）从一块积木绕过门直连组件区，虚线中段标注小字「定理保护之外」。整幅立于墨 .14 基座条上，附图注（图 01 格式：图注 11.5px + 1px 细线）。

**第二节 · 边界清单**（徽标：论文原文核实为主，个别标合理解读）
六条边界，排版用「编号 + 短句标题 + 两行正文」的清单式长排（编辑网格，禁卡片阵列）：
1. **撤销的正确性仍由作者负责**：框架保证到点执行撤销函数，但卡片上写的办法灵不灵，运行时不验证（第 59 页）。防得了「忘了写」，防不了「写错了」。
2. **内存状态不保留**：这套机制是「卸了重装」，组件自己的内存状态热重载后不保留，想留就得放进更长寿的依赖里。
3. **边界外收不回**：数据一旦发出系统（写盘、发包）就只剩两条路：扣住不发，或者事后补偿（删文件、退款）；补偿的数学保证需要另行验证。
4. **版本与命名是开放问题**：依赖按名字连接，接口漂移和键名撞车都会「连接成立但运行出错」；命名空间、peer 依赖、结构兼容三条路各有局限，论文自己承认没有统一解。
5. **循环依赖查得出但拆着疼**：从声明就能静态检出，不会死锁（只会永久休眠），但拆起来要新写专门的胶水组件；十个互相缠绕的组件，最坏要新写几十个胶水件。正确性和运行速度不受影响，疼的是写配置和理解系统的人。
6. **证据是观察性的**：单一生态、单一语言（TypeScript）、无对照实验、性能开销论文自己承认未量化。

**第三节 · 什么时候别用（本页版面重心，对照式排版）**（徽标：合理解读）
对照表：左列「场景」、右列「是否适用」，账页/ledger 式排版，1px 细线分行，禁三等分卡片阵列。五行：
| 场景 | 是否适用 |
| 一次性脚本、组件集合常年不动的工具 | 不适用：引入语境和生命周期管理是纯开销 |
| 性能极度敏感且高频触碰共享状态的路径 | 不适用：intercept 和 isolate 都有成本，具体多大没人数 |
| 真正的不可信代码 | 不适用：能力检查挡不住绕过代理的恶意代码，仍需独立沙箱 |
| 没有把握维持「都走语境」纪律的团队 | 不适用：纪律守不住，保证就是纸面的 |
| 自进化 agent harness（快速替换组件 + 拓扑频繁变动） | 适用：两个保证正好一一对应 |

「适用」那一行是本页 focal event 的落点：逐条显影走到它时可以给一个比其余行更实的落定（如实印加粗，不是颜色变化）。

**带走物槽位 · 采用前自查清单**（勾选清单形态，天然契合「先自查再决定用不用」）
版面收尾放一个可勾选的自查清单块（2px 墨线勾勒面板，IBM Plex Mono 编号），五问，视觉稿占位文案（正式文案 M3 定，可标「占位」字样于注释）：
1. 共享状态能否全部绑成语境键？有一条绕行，保证就不成立。
2. 组件是否真的需要运行中动态装卸？常年不动的集合不值得付这套开销。
3. 热路径是否高频触碰共享状态？intercept 与 isolate 的代价尚无数字。
4. 是否要跑不可信代码？本范式不替代独立沙箱。
5. 团队是否有把握长期维持「都走语境」的纪律？

## 五、自检（交付前逐条过）

1. node 脚本实算全页色值：C ≥ 0.02 的色值色相必须同属钴蓝（OKLCH 265±5°），C < 0.02 中性豁免；无第二色相。
2. node 实算 WCAG（8-bit 合成口径）：文字 ≥4.5:1，图解线 ≥3:1，结果写进设计说明注释。
3. grep 零命中：`—`、`–`、`Scroll to explore`（忽略大小写）、`linear-gradient`、`backdrop-filter`、`#000000`、`h-screen`。
4. 人工核：无三等分卡片阵列、无装饰圆点、每行元信息 `·` ≤1、无装饰性节号眉标、数字全部有出处。
5. 移动端 <960px 塌单栏，四档视口无横向滚动。
