# 08 深色主题样张 · 审记

对象：`50-design/08-深色主题样张.html`，由 `50-design/03-首页小样-OD/cordis-hero.html` 换色而来。红线沿用 `03-首页小样-OD/brand-spec.md:29`（小字 ≥4.5:1、图解线 ≥3:1），另按任务要求加一条：标题/正文 ≥4.5:1。

对比度全部为本机 Node 实算（node v22.23.2，Windows），WCAG 2.x 相对亮度公式。合成色的口径是先把 alpha 合成结果四舍五入到 sRGB 8-bit 再算对比度，与浏览器实际渲染一致，比浮点直算保守 0.01~0.02。OKLCH 与 sRGB 互转用 CSS Color 4 公式，做过回转验证：`oklch(0.196 0.017 268.8)` → `#12151D`，`oklch(0.776 0.086 269.6)` → `#A0B4EE`，双向无损，所以 CSS 里写 oklch 与注释里写 hex 是同一个颜色。复现代码见文末。

结论先行：单墨基色取 `#a0b4ee`，暗纸取 `#12151D`，浅色样张的透明度阶梯（.14/.20/.70/.78/.82/1）一档没动，全部文字与图解线过线。

### #6b8be6 淘汰细节

单墨页面要靠透明度分层级，所以基墨必须保证降透明度后仍过线。`#6b8be6` 本体 5.61:1 够 4.5，但合成后（8-bit 口径）：

| alpha | 合成值 | 对比度 | 4.5 线 |
|---|---|---|---|
| .82 | `#5B76C2` | 4.18:1 | 不过 |
| .80 | `#5973BE` | 4.02:1 | 不过 |
| .78 | `#5771BA` | 3.89:1 | 不过 |
| .70 | `#5068AA` | 3.39:1 | （≥3 过） |

保住 4.5:1 的最小 alpha 是 0.865，意味着整个阶梯要改成 .87/.90 一类的密档，且与浅色样张的阶梯断开。`#a0b4ee` 保 4.5 的最小 alpha 是 0.660、保 3 的是 0.485，原阶梯全部落在安全区。基墨取后者。`#6b8be6` 仍留在 02-配方里作正文级 accent（全不透明用法），本样张没有全不透明的第二档文字，所以没用到它。

### 对 02-配方的一处修正

`02-色彩配方-mono.md:78` 称 `#2058D4` "对比度只够大字与图形"。实算 2.96:1，低于 3:1：大字（WCAG AA 大字线就是 3:1）和图形线都不过。该值是 catalog 原值（colors.json:19），不需要重推，但深色主题里它任何角色都承担不了，比 02-配方记载的用途还要收窄一档。

## 复现

核心函数（与实际运行一致）：

```js
function srgbToLin(c){ c/=255; return c<=0.04045 ? c/12.92 : Math.pow((c+0.055)/1.055,2.4); }
function lum(rgb){ return 0.2126*srgbToLin(rgb[0])+0.7152*srgbToLin(rgb[1])+0.0722*srgbToLin(rgb[2]); }
function cr(a,b){ const l1=lum(a),l2=lum(b); const hi=Math.max(l1,l2),lo=Math.min(l1,l2); return (hi+0.05)/(lo+0.05); }
function hexToRgb(h){ h=h.replace('#',''); return [0,2,4].map(i=>parseInt(h.slice(i,i+2),16)); }
// 8-bit 口径：先合成取整，再算对比度
const paper=hexToRgb('#12151D'), ink=hexToRgb('#a0b4ee');
for(const a of [0.14,0.20,0.70,0.78,0.80,0.82,1.0]){
  const comp=ink.map((c,i)=>Math.round(a*c+(1-a)*paper[i]));
  console.log(a, comp, cr(comp,paper).toFixed(2));
}
```

OKLCH 互转为 CSS Color 4 标准矩阵（OKLab 三步 + 线性 sRGB gamma），候选亮度、临界 alpha 搜索（步长 0.005）与上面同一套函数。运行环境 node v22.23.2。
