## 这本书讲什么

论文回答的是一个问题：软件一边跑、一边换零件，怎样才能不散架。它给了两条规矩：每个改动当场交出撤销办法，时间上拆得干净；每个组件进门先交需求清单，空间上接得稳。再把两者拧进同一本总账。

书里把它们讲成两个词：「回执」和「插座」。全书十二页，一个落地页、十个章节、一份术语表：

| 章 | 讲什么 |
| --- | --- |
| 01 · 由来 | dsh 七周 24 万 star，它的地基是 2019 年一个聊天机器人框架里长出来的 |
| 02 · 问题 | VSCode 前 100 个扩展里，87 个卸载要重启；等 AI 开始自己改自己，这会变成灾难 |
| 03 · 一页纸 | 92 页论文压成一页：一句话、两道考题、三句口诀、五张字据 |
| 04–08 · 五个思想 | 每章配一个能亲手点的演示：拔插件、回执串、断供歇业、黑户计数器、乱按也不怕 |
| 09 · 抄作业 | 十五招整理成勾选清单，勾几招、复制给 AI 就能用 |
| 10 · 边界 | 什么时候别用它。最大的成本叫纪律 |
| 附 · 术语表 | 全书出现的词，一句话一个 |

页面上每个关键说法都标了论文页码，指上去能看到原文摘句。

## 三种读法

- **只有 5 分钟**：直接读 [03 · 一页纸](https://augustyang.win/cordis/paper/)，论文的骨架都在这里
- **想弄懂原理**：从 [01 · 由来](https://augustyang.win/cordis/origin/) 顺着读到 08，每章一个演示
